List 06 is `all_train_duplicates_deleted_(all but newest)`, list 12 is `all_test_duplicates_deleted_(...)`. Each names the files deleted when the ISIC releases 2016 to 2020 were merged and de-duplicated with FSlint, keeping the newest copy of each group. A line names the deleted file only, never the file it duplicates, so the lists hold no pairs. They name every ISIC 2018 image on both sides, presumably because newer releases ship the same files again (HAM10000 is part of the ISIC 2019 training set). Being listed therefore says nothing about a link between our train and test images; the perceptual hash below answers that. Cassidy's train-vs-test lists (07 to 11, not fetched) cover only the 2016 and 2017 test sets.

### Near-duplicates by perceptual hash

Every image gets a 256-bit perceptual hash; two images whose hashes differ in at most 24 bits count as near-duplicates. This also finds resized or re-encoded copies, not only byte-identical files.

- **PASS** the threshold of 24 of 256 bits catches altered copies: resized to 75 % and re-saved at JPEG quality 70, an image moves by at most 14 bits (median 4, 200 images)
- 87 near-duplicate pairs among all 11,427 images; 86 of them are two photos of the same lesion.
- **PASS** 0 near-duplicate pairs have their images in two splits

- Closest pair in two different splits: `ISIC_0027757` (nv, fit) and `ISIC_0032082` (nv, val), 34 bits apart.
